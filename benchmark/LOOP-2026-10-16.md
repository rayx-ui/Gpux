# macOS improvement loop, 2026-10-16

A local AgentX improvement loop over the macOS native build of this benchmark (`perf/agentx-macos-loop`,
based on PR #3's benchmark and PR #7's memory bounds; nothing pushed, no web, Android or iOS run).
The loop's records are in `.agentx/experiments/2026-10-15-gpux-mac-os-fast-mode-perf-and-memory/`;
the data of the closing run is [results/2026-10-16-macos-loop/](results/2026-10-16-macos-loop/),
set against the opening run (`results/agentx-baseline`, kept out of git).

## What was kept

| Change | Where it shows (fast mode on unless noted) |
|---|---|
| `devtools` Cargo feature: no per-element DevKit node, semantics strings or property setters without it | dashboard-clock CPU -16%, allocations -62% |
| Sized Core Text fonts kept per (font, size) | text-relabel CPU -40% (92 to 120 fps, fast mode on or off), uniform list -9% |
| Rgba colors cached per thread; one shared transparent default | hover-grid CPU -19%, allocations -43% |
| List layers hold 0.15 viewports of overscan (was 0.5) | data-table heap -13%, uniform-list heap -12% |
| Text leaves measured through an enum variant, not a boxed closure | allocations per frame -13% to -80% |
| Text-leaf settling in linear time; kept layout styles compared without hashing | div-cards, hover-grid -3 to -5% |
| A scroll container whose layer is expected to composite keeps the layout of its children (`KeptContent`) and requests it in prepaint only if the layer is painted after all | scroll-div-cards draw p50 3.2 > 2.2 ms (-31%), allocations -60% |

Part 3 (`.agentx/experiments/2026-10-16-...-part-3/`) added:

| Change | Where it shows (fast mode on unless noted) |
|---|---|
| An element's event listener and style lists are allocated on first use (`LazyVec`) | div-cards draw p50 -10%, dashboard-all-panels -6%; geomean of six scenarios CPU -2.3%, draw p50 -3.5% |

| `Color::opacity(0)` keeps the invisible twin of each color, which every filled quad and border pairs with the fill | hover-grid CPU -6%, allocations -15% |
| The empty font features of a default text style are one shared list per thread | hover-grid allocations -18%, text-relabel -11% |
| A text's single default run is held in place, not in a vector, when kept text leaves compare and shape | allocations -14% to -20% on text-relabel, dashboard-all-panels, tree-toggle |

Part 3 closing run against the run closing parts 1 and 2 ([results/2026-10-16-macos-loop-part-3/](results/2026-10-16-macos-loop-part-3/),
3 runs each, 24 scenario configurations): heap allocations per frame fall in every one, -2% to -30% with fast mode on
(animated-dots -47%, hover-grid -30%, dashboard-all-panels -29%, table-stream -28%, tree-toggle -28%, text-relabel
-27%) and -8% to -49% with it off. Footprint is unchanged (within 2 MB, except scroll-div-cards off, 138 > 151 MB, which
swings with how many tiles of the 4,000 cards the allocator keeps). CPU per frame is lower in 22 of 24 configurations
but the two runs differ by up to 40% in configurations nothing here touched (scroll-uniform-list off -36%), so the
single-run CPU column is not evidence; the alternated A/B figures in the table are.

Part 3 tried and reverted: recycling the base style boxes (allocations -67% on div-cards but draw p50 +6%), claiming
kept layout nodes and collecting their text leaves in one pass (within noise), and deciding "emoji" once per glyph run in
the Core Text shaper (within noise).

Tried and reverted: boxing the devtools semantics, a directional div overscan, 256 px tiles, a digit glyph
table (18% slower than Core Text's warm path in an A/B inside one binary), boxing the div interactivity,
hand-inlined length comparisons, a one-pass kept-node claim, and two Metal drawables (16 MB less, but the
GPU-heavy effects-cards ran 1.5 times as long on the main thread).

## Targets not met

- Scroll footprint with fast mode on against off, closing run: 1.30x (uniform list), 1.33x (variable list), 1.46x
  (div cards), 1.45x (data table); at the opening run 1.34x, 1.31x, 1.45x, 1.49x. The absolute footprint fell 2-7% with
  fast mode on, but the changes that lowered the Rust heap also lowered it with fast mode off, so the ratio barely moved.
  What remains is the visible tile textures (about 26 MB) and the window's three drawables; the peak Rust heap is 1.2x to
  1.7x (data table) the heap with fast mode off.
- Hover granularity: splicing works per nested view, so a hover change inside one big view (hover-grid's 1,600 cells) builds
  that whole view again, 4.3 ms; cells as views would splice. Element-level reuse inside a view was not attempted.
- dashboard-clock draw p50 is 1.4 ms in the benchmark build (target 1 ms; 2.4 ms in the opening run): it is bounded by work per retained element (claiming layout nodes,
  copying prepaint records, replaying primitives; about 0.9 us per element for 2,600), which needs a by-reference replay
  of unchanged stretches. scroll-div-cards draw p50 is 2.2 ms (target 2 ms): what is left is the application's own render
  of its 4,000 elements, which only skipping the owner view's render on scroll-only frames would remove.

## Reading the CPU column

`main_cpu_ms` is thread CPU time, and on this machine it moves with pacing and the CPU's frequency choice: the same
build reads 1.8 or 2.6 ms on effects-cards from one run to the next, and two builds' medians drift by up to 10%.
Small effects were therefore judged by alternating one binary with an environment switch, by allocations, or by
`sample` profiles (which agreed with the work, not the thread time, for the Core Text font cache on data-table).
Run `python3 benchmark/run.py --target macos` again before drawing a conclusion from any single scenario.
